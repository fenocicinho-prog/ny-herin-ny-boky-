🎯 Vue d'ensemble de la Plateforme

Cette plateforme est une marketplace de livres malagasy construite avec Next.js qui permet :

  • Aux clients d'acheter ou de louer des livres
  • Aux vendeurs de vendre leurs livres avec des plans d'abonnement
  • Système de paiement via Stripe ou Mobile Money
  • Gestion des utilisateurs avec authentification JWT
  • Base de données SQLite avec Prisma ORM
Stack Technologique :
Frontend: Next.js 16.2.9 | React 19.2.4 | TailwindCSS 4
Backend: API Routes Next.js | Prisma 6.12.0
Base de Données: SQLite
Paiement: Stripe | Mobile Money
Stockage: UploadThing (pour les images)

🏗️ Architecture du Système

Composants Principaux

1. Frontend (Client)

  • app/page.tsx - Page d'accueil
  • app/connexion/ - Authentification
  • app/inscription/ - Inscription (Client/Vendeur)
  • app/vendeur/ - Tableau de bord vendeur
  • app/client/ - Espace client
  • components/ - Composants React réutilisables

2. Backend API

  • app/actions/ - Serveur Actions Next.js
    • auth.ts - Authentification
    • books.ts - Gestion des livres
    • orders.ts - Gestion des commandes
    • subscription.ts - Gestion des abonnements
  • app/api/ - Routes API REST
    • stripe/webhook/ - Webhooks Stripe
    • uploadthing/ - Gestion des uploads

3. Base de Données

prisma/schema.prisma - Schéma de la base de données avec les modèles :

  • User - Utilisateurs (CLIENT/VENDOR)
  • Book - Livres avec prix d'achat/location
  • Order - Commandes avec statut de paiement

4. Services Externes

  • Stripe - Paiement par carte bancaire
  • Mobile Money - Paiement mobile (numéro de téléphone)
  • UploadThing - Stockage d'images dans le cloud

🔄 Flux Principaux

1. Flux d'Inscription

Utilisateur ↓ Choisit type (Client/Vendeur) ↓ Remplit formulaire (email, password, etc.) ↓ Validation Zod ↓ Hash password avec bcryptjs ↓ Crée record User dans BD ↓ Génère JWT token ↓ Redirige vers dashboard

2. Flux d'Achat de Livre

Client visite page livre ↓ Clique sur "Acheter" ou "Louer" ↓ Choisit méthode de paiement ↓ Crée commande (Order) status PENDING ↓ Si Stripe: redirection vers Stripe Checkout ↓ Si Mobile Money: reçoit numéro de vendeur ↓ Webhook Stripe confirme paiement ↓ Met à jour Order status à COMPLETED

3. Flux Ajout Livre (Vendeur)

Vendeur accède VendorBooksForm ↓ Upload image via UploadThing ↓ Remplit détails (nom, prix, catégorie) ↓ Soumet formulaire ↓ Crée record Book dans BD ↓ Associe au vendeur (vendorId) ↓ Affiche dans shop vendeur

4. Flux Abonnement Vendeur

Vendeur choisit plan ↓ TWENTY_BOOKS: 20 livres max UNLIMITED: livres illimités ↓ Paiement Stripe ↓ Webhook confirme ↓ Mise à jour User.subscriptionActive = true ↓ Vendeur peut ajouter livres

⚠️ Erreurs Courantes et Solutions

Erreur 1 : "Cannot find module 'next'"

Cause : Les dépendances ne sont pas installées
Solution : 
npm install
ou
yarn install
ou
pnpm install

Erreur 2 : "PrismaClientRustPanicError: Cannot find engine"

Cause : Prisma n'est pas correctement généré
Solution : 
npx prisma generate
npm run build

Erreur 3 : "ENOENT: no such file or directory .env"

Cause : Fichier .env manquant
Solution : Créez un fichier .env.local à la racine : 
# Base de Données
DATABASE_URL="file:./dev.db"

# Stripe
NEXT_PUBLIC_STRIPE_KEY="your_stripe_public_key"
STRIPE_SECRET_KEY="your_stripe_secret_key"

# UploadThing
UPLOADTHING_TOKEN="your_uploadthing_token"

# Mobile Money
MOBILE_MONEY_PHONE="+261340000000"

# JWT Secret (pour tokens)
JWT_SECRET="your_jwt_secret"

Erreur 4 : "Unexpected token < in JSON at position 0"

Cause : Le serveur retourne du HTML au lieu de JSON
Diagnostic : Vérifiez que :
  1. Les routes API sont dans le bon dossier app/api/
  2. Vous envoyez le bon Content-Type : application/json
  3. L'endpoint existe et retourne du JSON
  4. Le serveur est lancé correctement : npm run dev

Erreur 5 : "User not found" ou "Unauthorized"

Cause : Token JWT expiré ou invalide
Solution :
  1. Vérifiez le token dans les cookies/localStorage
  2. Vérifiez que JWT_SECRET est configuré
  3. Utilisateur doit se reconnecter
  4. Vérifiez la durée du token : exp: Math.floor(Date.now() / 1000) + 60 * 60 * 24 * 7

Erreur 6 : "Stripe webhook signature verification failed"

Cause : La clé secrète du webhook Stripe est incorrecte
Solution :
  1. Allez sur votre dashboard Stripe
  2. Webhooks → Endpoint → Clé secrète
  3. Copiez la clé avec le préfixe whsec_
  4. Mettez-la dans .env.local : STRIPE_WEBHOOK_SECRET="whsec_..."
  5. Redémarrez le serveur : npm run dev

Erreur 7 : "UploadThing token missing or invalid"

Cause : Token UploadThing manquant ou expiré
Solution :
  1. Créez un compte sur uploadthing.com
  2. Générez un nouveau token
  3. Ajoutez dans .env.local : UPLOADTHING_TOKEN="your_uploadthing_token"
  4. Redémarrez le serveur

Erreur 8 : "NEXT_PUBLIC variables not accessible"

Cause : Les variables sans le préfixe NEXT_PUBLIC_ ne sont pas accessibles au client
Solution : Assurez-vous que les variables exposées au frontend commencent par NEXT_PUBLIC_ 
# ✅ Accessible au client
NEXT_PUBLIC_STRIPE_KEY="your_stripe_public_key"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"

# ❌ Serveur seulement
STRIPE_SECRET_KEY="your_stripe_secret_key"
JWT_SECRET="your_jwt_secret"

Erreur 9 : "Book not found" lors de la récupération

Cause : L'ID du livre n'existe pas ou est invalide
Solution : 
// Dans app/actions/books.ts, vérifiez :
const book = await prisma.book.findUnique({
  where: { id: bookId },
  include: { vendor: true }
});

if (!book) {
  throw new Error('Livre non trouvé');
}

Erreur 10 : "Password hash comparison failed"

Cause : Password n'est pas hashé correctement lors de l'inscription
Solution : Assurez-vous d'utiliser bcryptjs : 
import bcryptjs from 'bcryptjs';

// Lors de l'inscription
const hashedPassword = await bcryptjs.hash(password, 10);

// Lors de la connexion
const isValid = await bcryptjs.compare(password, user.password);

⚙️ Configuration et Mise en Place

1. Installation Initiale

Étape 1 : Clonez le repo et installez les dépendances 
npm install
Étape 2 : Créez le fichier .env.local 
DATABASE_URL="file:./dev.db"
NEXT_PUBLIC_STRIPE_KEY="your_stripe_public_key"
STRIPE_SECRET_KEY="your_stripe_secret_key"
STRIPE_WEBHOOK_SECRET="your_webhook_secret"
UPLOADTHING_TOKEN="your_uploadthing_token"
JWT_SECRET="your_jwt_secret"
MOBILE_MONEY_PHONE="+261340000000"
Étape 3 : Configurez la base de données 
npx prisma generate
npx prisma db push
npx prisma db seed
Étape 4 : Lancez le serveur de développement 
npm run dev

Le site sera disponible sur http://localhost:3000

2. Configuration Stripe

  1. Créez un compte Stripe : stripe.com
  2. Allez dans les Clés API
  3. Copiez la Clé Publiable → NEXT_PUBLIC_STRIPE_KEY
  4. Copiez la Clé Secrète → STRIPE_SECRET_KEY
  5. Configurez les Webhooks :
    • Endpoint : http://localhost:3000/api/stripe/webhook
    • Événements : checkout.session.completed
    • Copiez la clé du webhook → STRIPE_WEBHOOK_SECRET

3. Configuration UploadThing

  1. Créez un compte : uploadthing.com
  2. Créez une nouvelle application
  3. Générez un token API
  4. Mettez dans .env.local : UPLOADTHING_TOKEN="your_uploadthing_token"`

4. Build pour la Production

Commande : 
npm run build
npm start

5. Variables d'Environnement Complètes

Variable Description Exemple
DATABASE_URL URL de la base de données SQLite file:./dev.db
NEXT_PUBLIC_STRIPE_KEY Clé publique Stripe (exposée au client) pk_test_51...
STRIPE_SECRET_KEY Clé secrète Stripe (serveur uniquement) sk_test_51...
STRIPE_WEBHOOK_SECRET Secret pour valider webhooks Stripe whsec_test_...
UPLOADTHING_TOKEN Token pour UploadThing sk_live_...
JWT_SECRET Secret pour les tokens JWT your_secret_key
MOBILE_MONEY_PHONE Numéro Mobile Money du vendeur +261340000000

🐛 Guide de Débogage

1. Activez les Logs

Ajoutez dans prisma/schema.prisma : 
generator client {
  provider = "prisma-client-js"
  previewFeatures = ["interactiveTransactions"]
}

model PrismaLog {
  id    String @id @default(cuid())
  message String
  createdAt DateTime @default(now())
}

2. Utilisez Chrome DevTools

Network Tab : Vérifiez les requêtes API
  • Status 200 = succès
  • Status 400 = erreur client
  • Status 500 = erreur serveur
Application Tab : Vérifiez les cookies/localStorage pour les tokens

3. Vérifiez les Logs du Serveur

Dans le terminal où vous avez lancé npm run dev, vous verrez les erreurs en temps réel. 
⨯ error: message détaillé
  at file.ts:line:column

4. Utilisez Prisma Studio

Commande : npx prisma studio

Ouvre une interface visuelle pour explorer votre base de données.

5. Vérifiez les Webhooks

Pour Stripe : Dashboard → Webhooks → Voir les événements
  • Green checkmark = webhook traité avec succès
  • Red exclamation = erreur dans le traitement

📊 Modèles de Données

User (Utilisateur)

{
  id: string               // Identifiant unique (CUID)
  email: string            // Email unique
  password: string         // Hash bcryptjs
  firstName?: string
  last?: string
  role: "CLIENT" | "VENDOR"
  companyName?: string     // Pour vendeurs
  location?: string
  subscriptionPlan?: "TWENTY_BOOKS" | "UNLIMITED"
  subscriptionActive: boolean
  books: Book[]            // Livres du vendeur
  orders: Order[]          // Commandes de l'utilisateur
}

Book (Livre)

{
  id: string
  name: string
  description?: string
  buyPrice?: number        // Prix d'achat (Ar)
  rentPrice?: number       // Prix de location (Ar)
  imageUrl?: string        // URL de l'image
  category: "SCIENCE" | "MALAGASY" | "LITTERATURE" | "HISTOIRE" | "AUTRE"
  vendorId: string         // ID du vendeur
  vendor: User             // Relation au vendeur
  orders: Order[]          // Commandes
}

Order (Commande)

{
  id: string
  type: "BUY" | "BORROW"   // Achat ou location
  paymentMethod: "STRIPE" | "MOBILE_MONEY"
  paymentStatus: "PENDING" | "COMPLETED" | "FAILED"
  amount: number           // Montant en Ar
  phoneNumber?: string     // Pour Mobile Money
  stripeSessionId?: string // Session Stripe
  bookId: string
  book: Book
  userId: string
  user: User
}

Les webhooks Stripe pointent vers l'URL de production
JWT_SECRET est une valeur sécurisée aléatoire
Tous les tests passent : npm run lint
Pas de console.log() ou code de debug dans la production
